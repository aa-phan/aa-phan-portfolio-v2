## Phase Goal

**As a** visitor, **I want to** open the deployed project URL and see a fast, themed hero in light or dark, **so that** hosting, CI, theming and motion risks are retired before content is built.

<objective>
Let a visitor switch light and dark: first visit follows the system, a stored choice wins, the page never flashes the wrong theme, and blocked storage never breaks anything. The tracer wires the whole path (head script, theme lib, toggle button, react-spring thumb through the animation barrel, persistence across reload) and proves it in a browser; the second task pins every edge with unit tests against the real inline script and browser tests with app JS blocked.

Implements D-07 and D-08 (IX-10 thumb). The thumb snapping under reduced motion lands in plan 02-07, which adds the single motion-preference provider.

Purpose: DSN-03, and the first real consumer of the src/anim layer.
Output: inline theme-init script, src/lib/theme.ts, animation tokens, ThemeThumb, the anim barrel, ThemeToggle, theme unit and browser tests.

Ordering: this plan runs alone in wave 4. Every plan from here on builds into dist/, serves the preview on port 4173 and runs the repo-wide verify chain in the one shared working tree (worktrees are off), so plans 02-05 to 02-09 run strictly one after another.
</objective>
