(1) contrast-check.mjs — a Node ESM script using only node: built-ins (fs, path, process). No package.json, no npm install. It is a verification tool for the tokens doc, not application code (Phase 2 may port its logic into a token-contrast test). Implement: hex parsing; OKLCH to OKLab to linear sRGB using Ottosson's published matrices; a gamut check (each linear channel within -0.0001..1.0001, otherwise the row FAILs as OUT-OF-GAMUT, because browser gamut mapping would change the rendered color); WCAG 2.x relative luminance (0.2126 R + 0.7152 G + 0.0722 B on linear channels); contrast (L1 + 0.05) / (L2 + 0.05), compared UNROUNDED against the threshold (4.499 fails 4.5) and printed to 2 decimals. Implement CSS color-mix(in oklch) semantics for derived tokens: mix(--a P%, --b) interpolates L and C linearly with weight P/100 on --a, hue along the shorter arc, and an achromatic color (C below 0.0001) adopts the other color's hue. Argument flags may appear before or after the doc path. Modes:
- --selftest: runs at least 9 checks and prints SELFTEST PASS n/n with exit 0, or one SELFTEST FAIL line per failed check with exit 1. Required checks: hex pairs 050315/fbfbfe = 19.73, 2f27ce/fbfbfe = 8.83, 2f27ce/050315 = 2.23, 433bff/050315 = 3.21, 7b75ff/050315 = 5.66, dedcff/fbfbfe = 1.29 (each within 0.01; values independently verified during planning); oklch(1 0 0) vs oklch(0 0 0) = 21.00; hex 2f27ce round-trips through OKLCH back to 2f27ce; a 50% mix of oklch(1 0 0) and oklch(0 0 0) has L = 0.5.
- --convert VALUE: given a hex prints oklch(L C H) (L as 0-1 decimal, 4 decimals), given oklch(...) prints hex. Used to author tokens and realtimecolors links.
- default, DOC [--require-chosen]: parse fenced blocks from DOC. Info string "palette X" (X = one uppercase letter) holds role lines "THEME TOKEN oklch(L C H)" (THEME is light or dark) and optional derived-override lines. Info string "derived" holds lines "THEME TOKEN mix(TOKEN_A P%, TOKEN_B)". Info string "pairs" holds lines "FG on BG CATEGORY USED-BY..." where CATEGORY is text (min 4.5), large (3.0), ui (3.0) or focus (3.0). Enforce per D-06: every palette defines exactly the 5 roles --text, --background, --primary, --secondary, --accent for both light and dark; a derived token given a literal color is an error (derived tokens are mix() only); every pair token resolves. First print one line per resolved token, "TOKEN PALETTE THEME NAME oklch(L C H) #rrggbb" (roles and derived tokens alike), then print one row per palette x theme x pair: "PALETTE THEME FG on BG CATEGORY RATIO min THRESHOLD PASS|FAIL USED-BY". Final line: "RESULT: PASS palettes=N checks=M" with exit 0, or "RESULT: FAIL failures=K" with exit 1. Exit 2 with an "ERROR:" line when no palette block or no pairs line is found, or any block fails to parse. With --require-chosen the doc must contain a line "Chosen palette: X" naming an existing palette block (print "CHOSEN X"), else exit 1.
