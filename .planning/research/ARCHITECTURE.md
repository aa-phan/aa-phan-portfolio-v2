# Architecture Patterns

**Domain:** Animation-heavy, mobile-first, single-page personal portfolio (React + Vite + TypeScript + Tailwind, static output on GitHub Pages)
**Researched:** 2026-10-08
**Overall confidence:** MEDIUM-HIGH (structure and patterns HIGH; third-party library internals and bundle sizes flagged per item)

---

## 0. Findings That Change the Plan (read first)

1. **The site is a static, build-time-data, zero-backend app.** No router, no store, no data fetching. The "architecture" is really four seams: (a) typed content, (b) CSS-variable design tokens, (c) an internal animation layer, (d) a build/deploy pipeline. Everything else is conventional React composition.
2. **Two animation libraries is fine ONLY behind one internal layer with a hard ownership rule.** `motion` (via motion-primitives) owns declarative / mount-unmount / layout / scroll / in-view. `react-spring` owns pointer-driven, velocity-preserving, interruptible physics. Sections and UI components never import either library directly (enforced by ESLint `no-restricted-imports`).
3. **There is a tooling gap: react-spring has no gesture engine.** Drag/fling/tilt-follow needs `@use-gesture/react` (the pmndrs companion to react-spring). It is not one of the four tools the user named. Surface as an ADR decision (recommend: adopt). Confidence MEDIUM (companion pairing is the long-standing documented pattern; confirm current version compatibility during the motion-spec doc).
4. **Reduced-motion coverage is NOT automatic.** Per motion.dev docs, `MotionConfig reducedMotion="user"` disables transform and layout animations only; opacity/color still animate, and parallax / scroll-linked / autoplay must be handled manually with `useReducedMotion`. react-spring needs its own hookup (`Globals.assign({ skipAnimation })`, plus a `useReducedMotion` utility exists in its docs). One internal hook must feed both. (HIGH: motion.dev docs; MEDIUM-HIGH: react-spring docs via search snippet, doc pages for Globals returned 404 on direct fetch, re-verify exact API when writing the motion spec.)
5. **GitHub Pages user-site naming constraint.** `aa-phan.github.io` (user site) is served from a repo named exactly `aa-phan.github.io`. The v2 work lives in `aa-phan-portfolio-v2`. Until cutover it will deploy at `https://aa-phan.github.io/aa-phan-portfolio-v2/` (project-site path), so `base` must be environment-driven, and asset URLs must never be hard-coded absolute paths. Cutover = archive/rename old repo, rename v2 repo to `aa-phan.github.io` (or push v2 into the old repo). Must be an ADR + runbook.
6. **Content has real problems to fix before it is typed** (see Section 4.3): dates/orgs smashed into a single `sub` string, inconsistent metrics across Experience vs Projects for the same Symbotic work (76% accuracy / 12% freight reduction vs "≥ 50%" / 25% / 24% / 36%), tiny favicon-grade logos (32px, 96px, 124px) that will be soft on retina and may vanish on dark backgrounds, no resume PDF (recruiters expect one), no hero/tagline copy, and unused `link` support in v1 (no project has links).
7. **motion-primitives is copy-in code, not a runtime dependency.** Installed via `npx motion-primitives@latest add <component>` (or copy/paste); requires `motion`, Tailwind, a `cn()` helper (`clsx` + `tailwind-merge`) and `lucide-react`. The project is labelled beta. Vendored components become owned code: wrap them, do not scatter them. (HIGH: motion-primitives.com/docs/installation.)

| Importer | May import | May NOT import |
|----------|-----------|----------------|

### 1.2 Component Boundaries

| Component | Responsibility | Communicates With |
|-----------|---------------|-------------------|
| `app/Providers` | Mounts `ThemeProvider` and `MotionPreferenceProvider` (which renders `MotionConfig` + sets react-spring `Globals`). Nothing else. | `anim/`, `hooks/useTheme` |
| `app/Page` | Imports typed content, renders sections in IA order, passes data down as props. Single seam between data and UI. | `content/`, `sections/` |
| `sections/*` | One section each: layout of its own content + choosing which animation wrappers to use. No data imports, no business logic. | `layout/Section`, `components/ui`, `anim` barrel |
| `layout/Section` | `<section id aria-labelledby>`, heading, `scroll-margin-top`, optional reveal. Guarantees every section has an anchor and an accessible name. | `anim` (`Reveal`), `Heading` |
| `layout/SiteHeader` + `MobileNav` | Sticky nav, in-page anchors, theme toggle, active-section highlight. Mobile: bottom or sheet nav (decide in IA doc). | `hooks/useActiveSection`, `ThemeToggle`, `anim` |
| `components/ui/*` | Design-system atoms. Style via semantic Tailwind tokens only (`bg-surface text-fg`). Press/hover feedback via `anim` primitives. | `lib/cn`, `anim` |
| `anim/MotionPreferenceProvider` | Single source of truth for "should we move?" (OS pref + optional site override). Configures both libs. | motion `MotionConfig`, react-spring `Globals` |
| `anim/declarative/*` (motion-owned) | `Reveal`, `Stagger`, `Presence`, `ScrollProgress`, `TextReveal`, `SharedLayout/Morph`. Thin wrappers over `motion/react` and vendored motion-primitives. | `anim/tokens`, `useMotionPreference` |
| `anim/physics/*` (react-spring-owned) | `Draggable`, `Magnetic`, `Tilt`, `PressSpring`, `useSpringValue` helpers. Pointer-driven, interruptible. | `@use-gesture/react`, `anim/tokens`, `useMotionPreference` |
| `anim/tokens.ts` | One spring/duration/ease vocabulary, exported in BOTH libraries' formats so the feel is consistent. | CSS motion variables (mirrored by hand and unit-tested) |
| `content/*` | Typed data modules + schema types + image registry. Pure data, no React. | `assets/` (image imports) |
| `hooks/useActiveSection` | IntersectionObserver over section ids; returns active id. | `layout/SiteHeader` |
| `styles/*` | Tokens (CSS variables), Tailwind `@theme` mapping, base resets, reduced-motion CSS guard. | consumed by everything via utilities |

### 1.3 Data Flow (explicit directions)

```
BUILD TIME
  content/*.ts ──(typed, `satisfies`)──> app/Page ──props──> sections ──props──> layout/ui
  assets/*.{jpg,png,svg} ──(vite-imagetools / hashed imports)──> content image fields

RUNTIME (all client-side, no network except same-origin assets)
  localStorage.theme ─┐
  prefers-color-scheme┴─> inline <head> script ──> <html data-theme> ──> CSS vars ──> every component
                              ThemeProvider (React) only mutates attribute + localStorage on toggle

  prefers-reduced-motion ─┐
  optional site override  ┴─> useMotionPreference() ─┬─> MotionConfig reducedMotion
        (localStorage)                                ├─> react-spring Globals.skipAnimation
                                                      └─> anim wrappers (`reduced` boolean branch)

  scroll position ──IntersectionObserver──> useActiveSection ──> SiteHeader (highlight)
  pointer/touch   ──@use-gesture──> react-spring SpringValues ──> animated.* (no React re-render per frame)
  project card click ──useState in Projects──> AnimatePresence / layoutId morph overlay (focus trapped)
```

No global state library. Three tiny contexts only: theme, motion preference, (optionally) active section. Everything else is props.

## 3. Patterns to Follow

### Pattern 1: Content-as-data with a single content seam
**What:** All copy lives in typed TS modules in `src/content/`. Only `app/Page.tsx` imports the data; sections receive it as props.
**When:** Always. There are ~30 content entries; JSX-inlined copy makes every future edit a code change, and v1's mixed `sub: "Spectrum: May 2025 – August 2025"` strings show where that goes.
**Why TS over JSON:** images are imported modules (hashed URLs, dimensions), types are compile-checked, `satisfies` catches missing fields, and no MDX/CMS is needed (blog/CMS is out of scope). Revisit only if a blog is added.
**Example:**
```ts
// content/schema.ts
export interface ImageAsset { src: string; alt: string; width: number; height: number; srcset?: string }
export interface DateRange { start: string /* YYYY-MM */; end: string | 'present'; label: string /* "Jun 2026 – Aug 2026" */ }
export interface Link { label: string; href: string; external: boolean }

export interface Experience {
  id: string; role: string; org: string; orgUrl?: string
  logo?: { light: ImageAsset; dark?: ImageAsset }   // dark variant for dark theme
  dates: DateRange; location?: string
  bullets: string[]
  highlights?: { value: string; label: string }[]  // "100K+" "events/day" -> scannable in seconds
  stack?: string[]
}
export interface Project {
  id: string; title: string
  context: { kind: 'personal' | 'internship' | 'hackathon' | 'course'; label: string }  // "Spectrum", "ECE 422C"
  dates: DateRange; stack: string[]; bullets: string[]
  links?: Link[]; image?: ImageAsset; featured?: boolean
  relatedExperienceId?: Experience['id']           // Suspect Genie -> Symbotic, A.T.L.A.S -> Spectrum
}
export interface Education { id: string; degree: string; school: string; location: string; dates: DateRange; gpa?: string; track?: string }
export interface SkillGroup { id: string; label: string; items: string[] }   // v1 used comma-joined strings
export interface Profile { name: string; tagline: string; bio: string[]; quote?: string; photo: ImageAsset; contacts: Contact[] }
export interface SiteContent { profile: Profile; experience: Experience[]; projects: Project[]; skills: SkillGroup[]; education: Education[] }

// content/experience.ts
export const experience = [ /* ... */ ] satisfies Experience[]
```

### Pattern 2: Two-layer design tokens, class- or attribute-switched, mapped into Tailwind v4 `@theme`
**What:** Layer 1 = primitive ramps (raw palette from the realtimecolors exploration). Layer 2 = semantic roles that flip per theme. Tailwind utilities point at semantic variables so components almost never need `dark:` variants.
**When:** Always. Realtimecolors outputs five roles (text, background, primary, secondary, accent) which map 1:1 onto semantic tokens, plus derived surface/border/muted tints.
**Example:**
```css
/* styles/tokens.css */
:root {
  --c-ink-950: #050315;  /* primitives: from realtimecolors export, names are ramp positions, not roles */
  --c-paper-50: #fbfbfe;
  /* ...ramps... */
  color-scheme: light;
  --bg: var(--c-paper-50);
  --fg: var(--c-ink-950);
  --surface: ...; --border: ...; --muted: ...;
  --primary: ...; --primary-fg: ...; --accent: ...;
  /* motion mirrors (JS tokens.ts is canonical for springs) */
  --dur-fast: 120ms; --dur-base: 220ms; --dur-slow: 420ms;
  --ease-out: cubic-bezier(.22,1,.36,1);
}
[data-theme="dark"] { color-scheme: dark; --bg: ...; --fg: ...; /* ...same names, new values... */ }

/* styles/index.css */
@import "tailwindcss";
@custom-variant dark (&:where([data-theme=dark], [data-theme=dark] *));
@theme inline {
  --color-bg: var(--bg);
  --color-fg: var(--fg);
  --color-surface: var(--surface);
  --color-primary: var(--primary);
  /* spacing/radius/shadow/font tokens here too */
}
```
Theme init (prevents flash; goes inline in `<head>` before CSS paint):
```html
<script>
  (function(){try{var t=localStorage.getItem('theme');
  var d=t?t==='dark':matchMedia('(prefers-color-scheme: dark)').matches;
  document.documentElement.dataset.theme=d?'dark':'light';}catch(e){}})();
</script>
```
Use `data-theme` (not `.dark`) because it also supports a future 3rd theme and mirrors the Tailwind-documented `@custom-variant` approach. Three-way toggle (light/dark/system): remove the key for "system". Also update `<meta name="theme-color">` on toggle. (HIGH: tailwindcss.com/docs/dark-mode.)

Rule: **no raw hex in components, ever** (lint with a simple grep CI check or Stylelint). Contrast ratios for every fg/bg pair in BOTH themes are tabulated in the tokens doc and unit-checked.

### Pattern 3: The internal animation layer ("small, owned, boring")
**What:** `src/anim/index.ts` is the only path through which the app animates. It exposes a handful of semantic components/hooks, not library primitives.

**Public API (target, keep it this small):**
```ts
// anim/index.ts
export { MotionPreferenceProvider, useMotionPreference } from './MotionPreferenceProvider'
export { Reveal, Stagger, StaggerItem, Presence, TextReveal, ScrollProgress, Morph } from './declarative'
export { Draggable, Magnetic, Tilt, PressSpring } from './physics'
export { springs, durations, eases } from './tokens'
```

**Library ownership rule (the decision the user asked for):**

| Interaction class | Owner | Why | Examples in this site |
|-------------------|-------|-----|----------------------|
| Mount/unmount, route-like transitions, presence | `motion` (`AnimatePresence`) | Declarative exit animations are `motion`'s strength | Project overlay open/close, mobile nav sheet, theme-crossfade |
| In-view reveals, staggered entrances | `motion` (`whileInView`, variants) | Cheapest, IntersectionObserver built in, `once` | Section headings, experience entries |
| Layout / shared-element morphs | `motion` (`layoutId`, vendored `MorphingDialog`) | react-spring has no layout engine | Project card -> detail |
| Scroll-linked values | `motion` (`useScroll`, `useTransform`) | Tight scroll integration; MUST be gated by reduced motion manually | Scroll progress bar, mild hero parallax |
| Text effects, number effects, ready-made polish | vendored motion-primitives (`TextEffect`, `AnimatedNumber`, `Tilt`, `Magnetic`, `Spotlight`, `Dock`...) | They exist and are tested against `motion` | Hero text, metrics count-up |
| **Pointer/touch-driven, velocity-aware, interruptible** | `react-spring` + `@use-gesture/react` | Springs keep velocity on release and can be retargeted mid-flight; this is the "tactile" differentiator | Draggable stickers/cards that fling and settle, press-squish buttons, magnetic CTA, toggle thumb |
| Simple hover/focus color changes | CSS transitions via tokens | No JS cost | Links, tag hover |

**Never:** both libraries animating the same element, or the same CSS property on two elements nested in a way that fights. If a motion-primitives component (e.g. `Tilt`, `Magnetic`) overlaps a react-spring physics wrapper, pick ONE implementation per interaction in the motion spec and delete the other from `anim/`. Vendored primitives that duplicate a physics wrapper stay unused.

**Wrapper contract:** every wrapper (a) reads `useMotionPreference()`, (b) renders a static/instant equivalent when `reduced`, (c) takes durations/springs ONLY from `tokens.ts`, (d) forwards `className`/`as`, (e) never hides content at initial CSS state (see Pattern 4).

**Tokens in both formats (keeps the two libraries feeling like one system):**
```ts
// anim/tokens.ts
export const springs = {
  snappy: { stiffness: 500, damping: 32, mass: 1 },
  gentle: { stiffness: 170, damping: 26, mass: 1 },
  bouncy: { stiffness: 300, damping: 14, mass: 1 },
} as const
export const motionSpring = (k: keyof typeof springs) => ({ type: 'spring' as const, ...springs[k] })  // motion format
export const rsConfig = (k: keyof typeof springs) => ({ tension: springs[k].stiffness, friction: springs[k].damping, mass: springs[k].mass }) // react-spring format
```
Both libraries use physical spring parameters, so one table can drive both (react-spring `tension`/`friction` map to stiffness/damping). Exact numbers are tuned in the motion spec; the point is a single canonical table. Confidence MEDIUM (parameter naming verified from general knowledge; tune empirically).

Avoid per-frame React re-renders: use `useSpring` with `animated.div` (writes to DOM directly) and `motion` values; never `setState` from gesture handlers on every move.

Bundle: both libraries ship (`motion` is large unless using `LazyMotion` + `m`; vendored motion-primitives import the full `motion` component, so LazyMotion would require patching them). Treat as a budgeted decision: measure after the first signature interaction with `vite-bundle-visualizer`; set a JS budget in the perf doc; code-split the Projects overlay and any heavy effect with `React.lazy`. Size figures not asserted here (LOW, unverified).

### Pattern 4: Reduced-motion strategy (layered, one source of truth)
**What:** Never rely on a single mechanism.

| Layer | Mechanism | Covers |
|-------|-----------|--------|
| L0 Progressive enhancement | Content is visible by default in HTML/CSS. Reveal wrappers set the hidden initial state only after mount on the client (via motion `initial` prop), and `<noscript>` content/styles guarantee visibility. | JS failure, slow hydration, crawlers, screenshots |
| L1 CSS guard | `@media (prefers-reduced-motion: reduce) { *,*::before,*::after { animation-duration:.01ms !important; animation-iteration-count:1 !important; transition-duration:.01ms !important; scroll-behavior:auto !important } }`; smooth scroll enabled only inside `@media (prefers-reduced-motion: no-preference)`. | CSS transitions/keyframes, anchor scroll |
| L2 `motion` | `<MotionConfig reducedMotion="user">` (or `"always"`/`"never"` from the site override). Auto-disables transform + layout animations; keeps opacity/color. | All `motion` components incl. vendored primitives |
| L3 react-spring | In provider effect: `Globals.assign({ skipAnimation: reduced })` (with deps, cleanup resets). Animations jump to target. | All spring physics |
| L4 Wrapper branches | Wrappers use `reduced` to: drop parallax / scroll-linked transforms, stop infinite loops and autoplay (text loop, infinite slider, shimmer), disable inertia/fling (keep user-initiated drag position 1:1), swap transforms for short opacity fades. | Things L2/L3 explicitly do not cover |
| L5 Non-motion feedback | Pressed/focus/selected states must read without motion (color, outline, shape). | Users with reduced motion still get feedback |
| Optional L6 | Visible "Reduce motion" toggle in footer/header persisted to localStorage; feeds `useMotionPreference`. | Users whose OS setting is off but who want calm; recruiters on shared screens |

**Single hook:**
```ts
// anim/useMotionPreference.ts
export function useMotionPreference(): { reduced: boolean; setOverride: (v: 'system'|'reduce'|'full') => void }
// reduced = override==='reduce' || (override!=='full' && matchMedia('(prefers-reduced-motion: reduce)').matches)
```
Provider listens to the media query `change` event (users toggle it live) and sets both libraries. Test with Playwright `emulateMedia({ reducedMotion: 'reduce' })` as a CI smoke test (no element has a running transform animation; all content visible).

**Mobile/touch corollaries:** hover-dependent effects (Magnetic, Tilt, cursor spotlights) enable only under `@media (hover:hover) and (pointer:fine)` (hook: `useHoverCapable`); touch gets a tap/press equivalent or nothing. Draggables set `touch-action` deliberately so page scroll is never trapped, and every draggable has a non-gesture alternative. Do not use `deviceorientation` (iOS permission prompt). Pause infinite animations when off-screen or tab hidden.

### Pattern 5: Single page, anchors, no router
**What:** One page, one `index.html`. Sections have ids (`#experience`). Nav uses plain `<a href="#experience">`; `scroll-margin-top` offsets the sticky header; native smooth scroll gated by reduced motion; `useActiveSection` highlights nav. Project detail is an in-page overlay (state local to Projects; optionally mirrored to `#projects/recipecart` via `history.replaceState` later).
**Why not a router:** there is exactly one document; routing adds a dependency and the GitHub Pages deep-link problem for zero benefit. Why not HashRouter: unnecessary, and `/#/x` URLs look worse when shared. Why not BrowserRouter+`404.html` hack: GitHub Pages cannot rewrite paths; the copy-index-to-404 trick works but serves real misses with HTTP 404 and is only needed if multi-route URLs appear (revisit if a blog ever ships). A custom `public/404.html` that simply links home covers stray URLs. (HIGH on constraint; MEDIUM on sources, which were community posts consistent with GitHub's documented behavior.)
**Accessibility requirements:** skip link; landmark structure (`header/nav/main/footer`); one `h1`; each section labelled by its heading; overlay uses a real dialog primitive (focus trap, Escape, inert background, focus restore). **Gap:** verify whether vendored `MorphingDialog` meets this; otherwise wrap `@radix-ui/react-dialog` or native `<dialog>` and have `motion` animate the content. Decide in ADR.

### Pattern 6: Asset pipeline
- **Images:** live in `src/assets/images/`, imported as modules (content-hashed, long-cache). Use `vite-imagetools` for build-time `avif/webp` + responsive `srcset` and intrinsic `width/height` (prevents CLS). Content `images.ts` registry maps ids to imports; schema carries `alt`, `width`, `height`. `public/` only for URL-stable files (favicon, `og-image.png` 1200x630, `robots.txt`, `resume.pdf`). Add `loading="lazy"` / `decoding="async"` below the fold; hero image `fetchpriority="high"`. (MEDIUM: vite-imagetools is the standard Vite choice; confirm current `?as=picture` syntax during the tooling ADR.)
- **v1 inventory to carry over:** `about-dj.jpg` (539x800 portrait, 89 KB, fine; re-export a 2x master if available), `logos/capitalone.png` (124x113), `symbotic.png` (96x96), `spectrum.png` (32x32). The logos are favicon-grade: acceptable at ~24px but soft on 2x/3x phones, and dark-mode contrast is unchecked. Action: source SVGs, or render logos on a fixed light "chip" surface in both themes. UT Austin and OdderTech have no logo (decide: monogram fallback component). Leave v1's template leftovers (`img-1..6`, `blog-*`, `cover_bg_*`, `loc.png`, Bootstrap/icomoon fonts, sass, js) behind.
- **Fonts:** self-host via `@fontsource-variable/<family>` imported in `main.tsx` (Vite hashes and bundles woff2). Do NOT use the Google Fonts CDN link v1 uses (extra origin, render-blocking CSS, privacy). Limit to 1-2 families / only used axes+subsets (`latin`), `font-display: swap` with a metric-adjusted fallback to minimise CLS; preload the primary face. The seed pair (Inter/Inter) is generic for a "memorable" brief; the tokens doc must evaluate alternatives (project requirement).
- **Icons:** `lucide-react` (already a motion-primitives requirement), import per-icon for tree-shaking; inline SVG for brand marks (GitHub/LinkedIn/Instagram are not in lucide's current brand set; use a small local SVG set).
- **Resume:** add `public/resume.pdf` (new asset, user to supply). Recruiters expect it; v1 has none.

### Pattern 7: CI/CD and deploy
Two workflows:
- **`ci.yml`** (pull_request + push): `npm ci` -> `typecheck` (`tsc --noEmit`) -> `lint` -> `test` (Vitest: content integrity, token contrast, anim tokens) -> `build` -> (optional) Playwright smoke + axe + reduced-motion emulation against `vite preview`.
- **`deploy.yml`** (push to `main` + `workflow_dispatch`): per Vite's official static-deploy guide: `permissions: contents: read, pages: write, id-token: write`; `concurrency: group: pages, cancel-in-progress: true`; steps `actions/checkout` -> `actions/setup-node` (LTS, npm cache) -> `npm ci` -> `npm run build` -> `actions/configure-pages` -> `actions/upload-pages-artifact` (`path: ./dist`) -> `actions/deploy-pages` in a separate `deploy` job with `environment: github-pages`. The Vite docs currently pin checkout v7, setup-node v7, configure-pages v6, upload-pages-artifact v5, deploy-pages v5 (by commit SHA); pin SHAs and let Dependabot bump them. Repo Settings -> Pages -> Source = "GitHub Actions". (HIGH: vite.dev/guide/static-deploy.)
- **`base`:** `base: process.env.VITE_BASE ?? '/'`. Pre-cutover workflow sets `VITE_BASE=/aa-phan-portfolio-v2/`; post-cutover (repo named `aa-phan.github.io`) it is `/`. Use module imports for assets and `import.meta.env.BASE_URL` for anything in `public/` referenced from JS; use relative or `%BASE_URL%` in `index.html`. Test the preview-path build, not just `/`.
- **Cutover runbook (ADR + `docs/deploy-runbook.md`):** (1) v2 deployed and verified at the project path; (2) archive/rename old `aa-phan.github.io` repo (history preserved, v1 can be re-hosted as a project page if wanted); (3) rename v2 repo to `aa-phan.github.io`; (4) set `VITE_BASE=/` ; (5) verify; (6) rollback = rename back / redeploy v1 tag. Alternative: push v2 into the existing `aa-phan.github.io` repo on `main` and keep the Actions workflow; simpler but loses the clean v2 repo history. Recommend rename path; user decides.
- **SEO/social (static host limitation):** crawlers/link unfurlers read only the initial HTML, so put title, description, canonical, OG/Twitter tags, and JSON-LD `Person` in `index.html`, and include meaningful `<noscript>` content. v1 meta description still describes the iPod; update. Full prerender (e.g. `vite-react-ssg` or a post-build `react-dom/server` script) is a LATE, optional ADR: valuable for no-JS/ATS crawlers, but adds complexity; default to CSR + noscript + JSON-LD.

## 5. Anti-Patterns to Avoid

### Anti-Pattern 1: Importing `motion/react` or `@react-spring/web` inside sections
**Why bad:** Spreads two APIs across the app, makes reduced-motion handling inconsistent, makes later replacement/removal of a library a refactor of every file.
**Instead:** Only `anim/` (and vendored `components/motion-primitives/`) touch the libraries; lint-enforced.

### Anti-Pattern 2: Both libraries on one element or one interaction
**Why bad:** Transform conflicts, jitter, unpredictable interrupts, double bundle cost for no gain.
**Instead:** Ownership table in Pattern 3; one implementation per interaction recorded in the motion spec.

### Anti-Pattern 3: Hiding content in CSS until JS reveals it
**Why bad:** Blank page on JS error, slow phones, crawlers, screenshots, reduced-motion users.
**Instead:** Default visible; `initial` hidden state applied client-side only inside wrappers; `<noscript>` rule.

### Anti-Pattern 4: Animating layout properties or React state per frame
**Why bad:** Jank on mid-range phones; spring `setState` loops.
**Instead:** Animate `transform`/`opacity` only (plus `layout` via motion where needed); springs write to DOM via `animated.*`; gesture handlers never `setState` per move.

### Anti-Pattern 5: Hand-rolled dark mode via `prefers-color-scheme` only, or toggle with FOUC
**Why bad:** Tailwind v4's default `dark:` follows the media query, so a manual toggle silently does nothing unless the variant is overridden; late theme application flashes the wrong theme.
**Instead:** `@custom-variant dark` on `[data-theme=dark]` + inline head script + semantic tokens.

### Anti-Pattern 6: Raw hex/px in components; `transition: all`
**Why bad:** Defeats the token system and light/dark; `transition: all` animates unintended properties.
**Instead:** Semantic Tailwind tokens; explicit `transition-[transform,opacity,color]` with token durations.

### Anti-Pattern 7: Hover-only or gesture-only interaction
**Why bad:** Project requires no desktop-only gestures; v1's wheel-drag-only scrolling was the exact trap (keyboard fallback existed, touch was OK, but concept was inherently modal).
**Instead:** Every gesture has a tap/click/keyboard equivalent; hover effects gated by `(hover:hover)`.

### Anti-Pattern 8: Router/state-library for a one-page static site
**Why bad:** Dependency + GitHub Pages 404 workarounds for no benefit.
**Instead:** Anchors + local state + three tiny contexts.

### Anti-Pattern 9: Google Fonts CDN link / absolute `/images/...` paths
**Why bad:** Extra origin and render-block; absolute paths break under the project-path (`/aa-phan-portfolio-v2/`) pre-cutover deploy.
**Instead:** `@fontsource-variable`, module-imported assets, env-driven `base`.

### Anti-Pattern 10: Letting vendored motion-primitives sprawl
**Why bad:** Beta library, untracked local edits, inconsistent reduced-motion behavior.
**Instead:** Install only components the motion spec calls for, keep them in `components/motion-primitives/`, log patches in an ADR, consume only through `anim/` wrappers.
